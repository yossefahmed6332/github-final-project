# Contributing

Thank you for your interest in contributing to this project!

## Getting Started

1. Fork the repository.
2. Clone your fork locally.
3. Create a new branch for your changes.

```bash
git clone <your-fork-url>
cd <repository-name>
git checkout -b feature/your-feature-name
```

## Making Changes

Before submitting a contribution:

* Follow the existing project structure and coding style.
* Keep changes focused and related to the purpose of the contribution.
* Add or update tests when necessary.
* Make sure the project builds successfully.
* Make sure all existing tests pass.

## Commit Messages

Use clear and descriptive commit messages.

Examples:

```text
Add user authentication
Fix appointment validation
Update repository documentation
Add tests for patient service
```

## Pull Requests

When submitting a Pull Request:

1. Push your branch to your fork.
2. Open a Pull Request against the main repository.
3. Clearly describe what you changed and why.
4. Mention any relevant issues.
5. Make sure all tests pass before requesting a review.

Example:

```bash
git push origin feature/your-feature-name
```

## Reporting Issues

If you find a bug or have a feature request, open an issue and provide:

* A clear description of the problem or request.
* Steps to reproduce the issue, if applicable.
* Expected behavior.
* Actual behavior.
* Any relevant error messages or screenshots.

## Code of Conduct

Please be respectful and constructive when communicating with other contributors.

## Questions

If you have questions about contributing, open an issue and provide enough context for others to help.
